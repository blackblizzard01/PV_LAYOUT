# Plan: RatedPower-style design engine + outputs

## Context

The goal is outputs that look and behave like RatedPower (reference screenshots in `reference/`): real sites shown over satellite imagery, structures coloured by terrain status, restricted areas, power stations, cables and roads, and views you can pan, zoom, rotate and toggle by layer. The current package (`plugins/pv-layout-design/pv_layout/`) can't do this, and the last L-shape run showed real **logic bugs**, not just cosmetic gaps:

| # | Bug (observed) | Where |
|---|---|---|
| B1 | Each row is a single point, so inverters stack on one N-S line and total DC cable is about 9 m for 760 kWp | `placement.py` `_group_rows_into_blocks` |
| B2 | Terrain is applied *after* placement, so excluded rows still count toward kWp and still get cabled | example pipeline order |
| B3 | Legend shows "Accepted (10)" next to "Earthworks (9)" because `n_kept` already includes earthworks rows | `plot.py` |
| B4 | Rows are checked only at their centre line, so the footprint can stick out past slanted edges | `geometry._row_segments_at_y` |
| B5 | Target trimming fills from the south first and leaves the north arms empty | `place_panels_polygon` |
| B6 | Azimuth is fixed at 180°, which is wrong for the southern hemisphere (should be 0°) | `energy.py` default |
| B7 | MultiPolygon or polygons with holes crash (`.exterior`); `buffer(-x)` can split an area | `plot.py`, `apply_setback` |
| B8 | Earthworks volume assumes a 200 m row width everywhere | `terrain.apply_terrain_limits` |
| B9 | Elevation lookup is a Python loop per point, so 50 MWp sites will be very slow | `DEMGrid.elevation_at` |
| B10 | Printing `²`/`³` fails on some Windows consoles | examples |

**Decisions (from the user):**
- First deliverable: PNGs plus standalone HTML viewers. The Streamlit app comes later, only if needed.
- Sites come from real KML/GeoJSON files in lat/lon.
- Terrain sources: synthetic, GeoTIFF, and an online SRTM download (cached).
- Per-table irradiation heatmap: skipped for now.
- At least **5 real-location examples**, each testing different things, each checked against expected results.

The existing Layer-1/2/3 public functions and all 98 tests stay as they are. The new engine sits beside them and reuses their formulas.

## Target architecture (new modules in `pv_layout/`)

```
geo.py          KML/GeoJSON → shapely in local UTM metres (pyproj); inverse transform for output
site.py         Site: available areas, restricted areas, usable_area(setbacks) → MultiPolygon
tables.py       StructureSpec + tile_tables(): per-structure (table) placement, fully inside usable area
terrain.py      (extend) vectorised elevations_at(); per-table slopes/classification; GeoTIFF + OpenTopography loaders
blocks.py       strings → inverter blocks (recursive capacity bisection) → power stations; Manhattan cable routing
design.py       DesignConfig (TOML via stdlib tomllib) + run_design() orchestrator → DesignResult
render/png.py       site plan, slope map, KPI panel (matplotlib PolyCollection)
render/map_html.py  2D satellite map (folium/Leaflet), layer toggles + popups
render/view3d_html.py 3D terrain + tables (plotly Mesh3d/Surface), rotate/zoom
__main__.py     CLI: python -m pv_layout run <config.toml> --out <dir>
```

**Pipeline order** (fixes B2): site → usable area → tables → terrain filter → strings → blocks/inverters → power stations → cable routes → losses → BoQ → energy → renders + `summary.json` + `boq.csv`.

### Reuse (do not rewrite)
- `geometry.compute_pitch`, `_winter_solstice_min_elevation`, `recommend_tilt`, `compute_gcr`, `apply_setback`
- `electrical.string_sizing` (modules per string), `select_conductor_area` (cable sizing per route)
- `losses.cable_loss`, `losses.transformer_loss`, `CableSpec`
- `placement.PlacementResult`: `blocks.py` fills one in, so `compute_all_losses` and `boq.bill_of_quantities` work unchanged
- `energy.annual_energy_yield` (pass `azimuth_deg` = 180 north / 0 south, which fixes B6; pass a cached PVGIS TMY)
- `terrain.DEMGrid`, `_earthworks_volume` logic (vectorised, real per-table width, which fixes B8)

## Phases

### Phase 1: Geometry core (fixes B4, B5, B7)
- `geo.py`:
  - Parse KML with stdlib `xml.etree` (Placemark/Polygon, outer/inner boundaries, Z ignored) and GeoJSON (Feature, FeatureCollection, MultiPolygon).
  - Role comes from the `role` property or name prefix (`AA-*` = available, `RA-*` = restricted, matching RatedPower naming).
  - Auto-pick the UTM EPSG from the centroid: 326xx north, 327xx south.
  - Run `shapely.make_valid` and drop slivers under 1 m².
- `site.py`: `usable = (available − restricted.buffer(ra_setback)).buffer(−perimeter_setback)`. Always returns a MultiPolygon. Raises an error naming the area that was erased.
- `tables.py`:
  - `StructureSpec(modules_along=28, modules_high=2, orientation="P", gap_ew=0.5, tilt, post_height)`.
  - For each row band (south and north edges), intersect the full band with usable, tile tables along x, and keep only those where `shapely.covered_by(table_box, usable)` (vectorised shapely 2).
  - Output arrays: `centers (N,2)`, `polys`, `row_id`, `n_modules`.
  - Mode `"max"` fills everything. Mode `"target_kwp"` drops tables farthest from the site centroid until the target is met, so trimming is no longer one-sided.
- Optional internal roads: N-S corridors every `road_spacing_m`, subtracted from usable before tiling. Perimeter road comes from the setback.

### Phase 2: Terrain (fixes B8, B9)
- `DEMGrid.elevations_at(xs, ys)`: vectorised bilinear interpolation. NaN/nodata (−32768) is masked; warn if coverage is under 99%.
- `load_geotiff(path)` (optional `rasterio`): sample in the DEM's own CRS by inverse-transforming table points, so no raster reprojection is needed.
- `fetch_srtm(bbox, api_key, cache_dir)`: OpenTopography `globaldem` API via `urllib`, cached as `.tif`. Gives clear errors for a missing key, timeout or HTTP 4xx. Works offline from the cache.
- Per-table classification: N-S slope (south edge vs north edge) and E-W slope (table ends), using thresholds from Design_Methodology §5.5.2.
- Status values are `accepted` / `earthworks` / `excluded`, all mutually exclusive (fixes B3 at the data level).

### Phase 3: Electrical (fixes B1)
- Strings: `string_sizing` gives modules per string; strings are assigned along each table.
- Blocks: recursive capacity bisection of table centres (split on the longer bbox axis at the capacity median). This is deterministic, compact, and keeps blocks balanced (±10%) to `inverter_kw × DC/AC ratio`.
- Inverter types:
  - `central`: inverter at the block centroid, snapped to the nearest road or row gap.
  - `string`: inverters spread through each block.
- Power stations: grouped by `ps_kva` with the same bisection. A station is placed at the AC-weighted centroid, snapped outside the tables.
- Cables: Manhattan routes (along the row gap, then along the N-S trench). Store the polylines for rendering and the lengths for losses. Conductor size per route comes from `select_conductor_area`.
- Fill `PlacementResult`, then reuse `compute_all_losses` and `bill_of_quantities`.

### Phase 4: Renderers
- `render/png.py` writes:
  - `layout.png`: available area (grey), restricted (red hatched), tables as one `PolyCollection` (blue / amber / red), block tint, power stations, MV cables, roads, AA/RA labels, north arrow, scale bar, KPI title block. Handles MultiPolygon and holes (fixes B7). Optional satellite basemap via `contextily` if installed.
  - `slope.png`: DEM slope bands green <5%, orange 5–10%, red 10–15%, purple >15% (Design_Methodology §5.2.2).
  - `kpis.png`: loss waterfall and energy summary.
- `render/map_html.py` (folium): Esri World Imagery and OSM basemaps. Layer groups match RatedPower's panel: Available areas, Restricted areas, Accepted / Earthworks / Excluded structures, Inverter blocks, Power stations, MV cables, Roads. `LayerControl`, popups (table id, slopes, kWp, block), and a KPI box. If there are more than 20k tables, merge per status/row with `unary_union` to keep the HTML small.
- `render/view3d_html.py` (plotly): DEM `Surface` with an adjustable vertical-exaggeration preset, tables as tilted quads in one `Mesh3d` per status at terrain + post height, and power-station markers. `write_html(include_plotlyjs=True)` so it works offline.

### Phase 5: Five real-location examples, CLI, validation
`examples/sites/<name>/` contains `site.geojson|kml`, `config.toml`, cached `dem.tif` (where used), cached `pvgis_tmy.csv`, and `expected.json`.

The polygons are illustrative parcels drawn at real coordinates, not actual project boundaries. Any of them can be swapped for your own KML.

| # | Site | What it tests |
|---|---|---|
| 1 | **Bhadla, Rajasthan IN** (27.5°N, 71.9°E), flat desert, ~25 MWp | Baseline geometry/GCR, multiple power stations, central inverters, PVGIS yield cross-check |
| 2 | **Ahmedabad outskirts IN** (23.0°N, 72.6°E), **KML** input | Holes and restricted areas (pond + HV corridor buffer), a road splitting the site into a MultiPolygon, setbacks |
| 3 | **Hilly Fukushima JP** (~37.4°N, 140.4°E), real SRTM DEM | GeoTIFF + OpenTopography cache, earthworks/exclusion, cut/fill, 3D view |
| 4 | **Darlington Point NSW AU** (34.6°S, 146.0°E) | Southern hemisphere: north-facing azimuth 0°, June-solstice pitch, DC/AC ratio, string inverters |
| 5 | **Cambridgeshire UK** (52.3°N, 0.1°E) | High latitude: large pitch / low GCR, high tilt, internal roads, low-irradiance yield |

Each `expected.json` stores reference values with tolerances:
- Specific yield within ±10% of a stored PVGIS PVcalc reference (URL and date recorded).
- GCR, `n_tables`, kWp, `n_inverters`, `n_power_stations` as a regression snapshot.
- Sanity bands: 0.4–1.2 MWp/ha; terrain fractions for site 3.

CLI: `python -m pv_layout run examples/sites/bhadla/config.toml --out out/bhadla`. It forces UTF-8 stdout (fixes B10) and writes all PNG/HTML/JSON/CSV outputs.

### Phase 6 (later, only if needed)

- Per-table irradiation heatmap with terrain-aware inter-row shading.

## Error handling / technicalities checklist
- Invalid or self-intersecting polygons → `make_valid`, warn. Empty usable area or zero tables → error that includes pitch, usable ha, and the largest interval width.
- UTM zone auto-pick, including the southern hemisphere. All outputs are inverse-projected back to WGS84 for the HTML map.
- DEM: nodata masking, coverage check, CRS mismatch handled by point-sampling in the DEM's own CRS.
- Network (OpenTopography, PVGIS, map tiles): timeouts, clear messages, cache-first. Tests never touch the network.
- Optional dependencies, as extras in `pyproject.toml`: `geo` = pyproj, `viz` = folium + plotly (+ contextily), `dem` = rasterio. If one is missing, `ImportError` names the exact `pip install "pv-layout-design[...]"`.
- Equator branch (lat <5° gives tilt 5°), and fewer tables than one inverter block both get covered by unit tests.
- Performance: shapely 2 vectorised predicates and numpy DEM sampling. Target under 30 s for site 1, enforced by a timing test (marked `slow`).
- Determinism: no randomness in bisection; any remaining k-means uses fixed seeds.

## Verification
1. `pytest plugins/pv-layout-design/tests/ -v`: the original 98 tests plus new unit tests all pass, with no network access.
2. `test_examples.py` runs all 5 sites end to end and asserts the geometric invariants:
   - Every table is `covered_by` usable.
   - No table intersects a restricted area.
   - No tables overlap.
   - Σ string modules equals the total modules.
   - Voc_cold × N ≤ V_sys.
   - Each block's kWp is within ±10% of its target.
   - Manhattan cable length ≥ Euclidean.
   - Values match `expected.json` within tolerance.
3. Render smoke tests: PNGs are non-empty; `map.html` contains every layer name; `view3d.html` exists and contains plotly.
4. Manual: run the CLI for each site, view each PNG (I'll inspect them visually), and open `map.html` / `view3d.html` in a browser to confirm pan/zoom/rotate and layer toggles work.
5. Cross-check sites 1, 4 and 5 against PVGIS PVcalc (stored references). Specific yield must be within ±10%.
